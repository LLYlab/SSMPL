# SSMPL 原理解析与优势

> 一份写给朋友的“精妙算法”说明书：为什么一个**纯静态、没有后端的网站**，能做出需要服务器才能做到的事——**真正的、可配置的内容权限控制**。

---

## 1. 一句话概括

> **正文用一把随机密钥 K 加密（可逆）；密码只用来“包住” K；密本 = 密码派生值 ⊕ K。**
> 于是：**没有密码就解不开；换密码／加人／收人，正文一个字节都不用重加密。**

---

## 2. 想解决的问题

普通个人博客放敏感内容，通常要么：

1. 直接公开（没门槛）；
2. 用 base64／固定异或“加密”（**一眼可还原，纯糊弄**）；
3. 上后端做账号登录（**要服务器、要数据库、要域名配置、要维护**）。

静态托管（GitHub Pages 等）**根本不给你跑后端**。那能不能用一个纯静态方案，做到"内容真被加密、需要有口令才能看、还能按人按篇给权限"？——这就是这套算法做的事。

---

## 3. 核心思想：分层 + “密本”隔开两层

关键是把**“加密内容的密钥”**和**“用户的密码”**彻底分开，中间用**密本**连起来。

```
第 1 层（内容层，可逆）：  正文  --AES-256-GCM(随机密钥 K)-->  密文
第 2 层（密码层，单向）：  密码  --PBKDF2-HMAC(盐, 迭代)-->  P   (32 字节)
密本（连接层，公开）：     密本 = P ⊕ K    （“密码派生值”与“内容密钥”的差）
```

- 只有**密码派生值 P** 和 **内容密钥 K** 做了异或，产物**密本**可以公开存放。
- 内容密文与密码之间**没有直接关系**，只通过密本这一条路连接。

---

## 4. 一步一步拆给你看

### (0) 一个类比

把正文当成**锁进保险箱的宝物**：
- 保险箱本身用**随机钥匙 K** 锁上（`AES-256-GCM`）。
- 你**不把 K 直接告诉任何人**。
- 你贴一张纸条（**密本**），上面写着：“**K = 你的密码换算出的数 ⊕ 纸条上的数**”。
- 想开箱的人：先拿自己密码换算出一个数（P），**再把纸条上的数和它异或**，就能还原出 K，从而开箱。
- 密码错 → 还原出的 K 是错的 → 保险箱（GCM 认证标签）**拒绝打开**，于是知道密码错了。

### (1) 加密 / 制作（后端做一次）

```
输入：正文、密码 X、配置(哈希/迭代/salt)
1. 随机生成 32 字节 K
2. 用 K 做 AES-256-GCM 加密正文  ->  {iv, ct, tag}      // 可逆
3. P = PBKDF2-HMAC-SHA256/SHA512(X, salt, iterations)   // 单向，推不回 X
4. 密本 = P ⊕ K                                          // 32 字节
5. 存：{ name: { iv, ct, tag, books:[密本] } }
```

- `books` 里的**每一条密本 = 一个用户的密码包住这篇的 K**。
- 加密一次，`K` 固定，之后所有权限操作都只动 `books`。

### (2) 解密 / 读取（前端做，用户本地）

```
输入：密码 X'、这篇文章的 {iv, ct, tag, books}
1. P' = PBKDF2(X', salt, iterations)
2. 对 books 里每条密本：
      K = P' ⊕ 密本
      用 K 尝试 AES-256-GCM 解密
      成功 -> 正文出来，结束
      失败(认证标签对不上) -> 这条密本不是你的，试下一条
3. 全部失败 -> 密码错误
```

- **AES-GCM 自带认证标签**，这非常关键：只有“对的 K”才能通过校验。这让“**判断密码对不对**”变得**零误差**——不用多存任何校验信息，也不会把“错的密码”误判成对的。
- 所以**多密码**天然支持：一篇里塞几条密本，不同密码各解各的，互不干扰。

### (3) 为什么“按文章、按用户”给权限能实现

- 一篇的 `books` 是**独立**的，里面的每一条密本都只对这“一篇”有效（它包的是这一篇的 K）。
- **授权某人看某篇**：往这一篇的 `books` 里**加一条**该用户密码的密本。
- **不让某人看某篇**：这一篇的 `books` 里**不放**他的密本 → 他用自己密码算出的 K 对不上，解不开。
- **收回某人的某篇**：只从这一篇的 `books` 里**删掉**他那条密本。

于是“张三能看 A、B；李四只能看 B；管理员全看”，就在一个公开 JSON 里靠**密本的有无**表达出来了。

### (4) 为什么换密码／加人／收人都不用重加密

因为它们全都**只动密本、不动正文**：

| 操作 | 做法 | 正文密文 |
|---|---|---|
| 加一个密码 | 同一篇，按新密码再算一条密本，`books.push` | 不动 |
| 换密码 | 把该密码对应密本删掉，再按新密码加一条 | 不动 |
| 收一个人 | 把他那条密本从这篇 `books` 里删掉 | 不动 |

> 核心：**内容密钥 K 与密码完全解耦**。K 只跟内容绑定；密码只通过密本跟 K 绑定。权限变了，K 不用变（也就永远不用重新加密正文）。

---

## 5. 为什么“密本”这一步很精妙

这是整套算法的灵魂：

- **让“内容加密”和“口令”解耦**：K 随机、独立、一次性；密码只负责“包住”K。
- **权限变更 = 一次异或**：加人／换密码／收人，只是**重算或增删一条密本**，`O(1)`，**正文零开销**。
- **载荷最小**：每篇只存**一份密文**，是 **O(篇数)**，不是 O(用户数 × 篇数)。真·多用户加密系统每加一个人就要给每篇重加密一份，这里完全不用。
- **单向密码**：`P` 是 PBKDF2 的结果，**拿不回密码**；密码不落盘、不上传，没有后端可拖库。
- **无需额外校验信息**：GCM 认证标签自动当“密码是否正确”的判据。

一句话：**它把“贵”的那些操作（重加密、按用户多存密文）全部变成“便宜”的操作（重算一段 XOR）。**

## 6. 安全性（讲清楚“好”和“边界”）

### 它做得好的
- **是真加密**：AES-256-GCM（认证加密）/ AES-256-CBC+HMAC，不是 base64 或写死 key。
- **口令单向、不入库、不上传**：本地 PBKDF2 派生；没有密码库、没有服务器可被攻破。
- **解密只在用户浏览器**：整站可下载，但没口令就是乱码。
- **口令错误零误差**：GCM 认证保证“非正确口令必失败”。

### 边界（必须诚实说）
- 载荷公开，攻击者可**离线穷举**：试密码 → 算 P → `K=P⊕密本` → 看 AES 标签对不对。所以**安全性 = 密码强度 × 迭代次数**。
- 这是**口令级权限**，不是**服务器式账号系统**：没有登录态；没法远程踢掉“已经存了密本”的人；拦不住用户转借密码/密本。
- “按人按篇”的分辨靠**每用户一个唯一密码**；两人同密码就分不开。

### 怎么更安全
换**强口令**、把**迭代次数**拉高（如 60 万+）、每个用户用**不同**密码。这些都不需要重加密正文。

## 7. 优势，逐条讲为什么重要

| 优势 | 为什么重要 |
|---|---|
| **纯静态就能跑** | GitHub Pages 等直接托管，无服务器、无数据库、无运维；也就没有后端可被攻击。 |
| **真加密** | 内容用标准认证加密，不是骗小孩的混淆；贴出来是密文就是密文。 |
| **免重加密的权限变更（核心）** | 加人/换密码/收人/按人按篇授权，只动一段 XOR；正文一个字不改，`O(1)`。 |
| **载荷最小** | O(篇数) 不是 O(用户×篇数)；一篇一份密文，体积可控。 |
| **密码不出浏览器** | 单向派生，不落盘、不上传；无密码库可拖。 |
| **跨语言、一套规格** | JS（浏览器 WebCrypto + Node）/ Python / C++（OpenSSL）算法一致、互相能加解密。 |
| **参数可调** | 哈希、迭代次数、加密方式都能改，可按需求权衡性能与抗爆破。 |
| **离线抗爆破（靠口令）** | 高迭代 + 强口令即可；同时不引入任何在线弱点。 |

## 8. 跟“常见做法”比一比

| 方案 | 真加密 | 免重加密换钥 | 载荷 | 密码安全 | 能否按人按篇授权 |
|---|---|---|---|---|---|
| base64 / 固定异或 | ❌ 纯混淆 | — | 大 | 无 | ❌ |
| 每用户重加密一份 | ✅ | ❌ 每加一人重加密 | O(用户×篇) | 好 | ✅ 但超贵 |
| **本方案（密本）** | ✅ | ✅ | **O(篇)** | 单向、不入库 | ✅ 靠密本有无 |
| 服务器账号鉴权 | ✅ | — | — | 好 | ✅ 但需后端 |

---

## 9. 适合的场景

- 静态博客/文档站，把**部分内容**设为“有口令才能看”。
- 小圈子分享：给朋友**按人按篇**授权，不用给整站密码。
- 任何**不能跑后端**、又想“真加密 + 权限”的托管场景。

---

## 10. 结尾

这套东西的巧处不在“发明了新密码学”，而在**把现成的密码学组合得刚刚好**：随机密钥加密内容、口令单向派生、用“密本”把两者**解耦**。换来的是——**静态站也能有真加密、真权限、而且权限变更几乎零成本**。
